# simple-yurii-note

`yurii_PKM` の v2 形式から、**Child セクションを無くして本文に一本化**した
シンプル版。構造は `### Parent` と `### BackLink` の 2 つだけ。
（本文中の `##` 見出しと衝突しないよう 3 つの `#` を使う。
Vim の autoload/関数名はハイフン不可のため内部的に `simple_yurii_note` を使う）

## ノート形式

```
---
time: 2026-09-27 12:00:00
title: ノートA
---
# ノートA

本文。ここに子へのリンクを普通に書く。これが「子」になる。
[ノートB](260927120000.md) について…

### Parent
[ノートP](260927110000.md)
### BackLink
[ノートC](260927130000.md)
```

### 考え方

- **本文 = 子（outgoing）**。`## Child` セクションは無い。本文にリンクを書けば、
  相手がこのノートの子になる。
- **`### Parent`** … このノートの親（incoming）。子を作ったコマンドが相手側へ
  書き込む。sync は死んだリンクの掃除だけ行う。
- **`### BackLink`** … 本文でこのノートにリンクしているが、親ではないノート。
  sync が自動生成する（手で書いてもよいが sync が上書きする）。

### Parent と BackLink の決まり方

- `zn` / `Enter` などで**新規ノートを子として作る**と、その新規ノートの
  `### Parent` に「元々開いていたノート」が入る。
- `\l` などで**既存ノートへリンクする**ときは「今開いているノートを親に
  するか」を聞く。はい → 相手の `### Parent` に入る。いいえ → 何も書かず、
  sync が相手の `### BackLink` に入れる。
- つまり **本文リンクは常に張られる**。相手側で `Parent` か `BackLink` かが
  決まる。

## コマンド / マッピング

| キー | 動作 |
| --- | --- |
| `zn` | 子ノートを新規作成。本文にリンクを 1 本置き、新ノートの Parent に今のノートを書く |
| `zk` | グループノートを新規作成（front matter に `group: true`）。リンクと Parent は `zn` と同じ |
| `\l` | 既存ノートへのリンクを本文に張る。「今のノートを親にする？」と聞く |
| `:SSync` | ルート全体を同期（Parent の死にリンク削除 + BackLink 再生成） |
| 保存時 | 自動で `update_one` 相当を実行 |

## ルート

`g:simple_yurii_note_root` を PKM ルートにする。未設定なら `index.md` を
持つ親ディレクトリを自動探索する。

## 同期エンジン

`python/simple_sync.py`

```
simple_sync.py update      ROOT
simple_sync.py update_one  FILE ROOT
```
