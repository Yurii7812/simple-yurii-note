# 06 引き継ぎ（新しいAI向け）

## 最初にやること

1. このフォルダの `README.md` → `01`〜`05` を読む。
2. プラグイン実体 `~/.vim-simple-yurii-note/simple-yurii-note` を把握。
3. ノート実体 `~/files/yurii-note` を見る（`index.md` が入口）。
4. `~/.config/opencode/AGENTS.md` と skills（特に `pkm-system`）を読む。
5. 変更したら **push まで**（日本語コミット）。

## 重要な不変条件

- ノートのセクションは `### Parent` / `### BackLink`（`#` 3つ）。**`### Child` は使わない**。
- 子は**本文リンク**。本文に書けば子になる。
- `### Parent` は**手書き管理**。同期は追加・削除しない（表示名だけ追従）。
  ただし**消えたファイル（存在しない `.md`）へのリンク行は掃除する**（`_prune_dangling()`）。
- `### BackLink = incoming − Parent`。Parent にあるものは BackLink に出さない。
- `index.md` は**セクションを持たない**（本文の裸リンクが子）。
- `zn`/`zk` の `Enter` は「本文があれば本文の下に空行1つ＋リンク / 無ければ余白を保って Parent 直上にリンク」。

## よくある落とし穴

- **`##`（2つ）で書く**: 同期が反応しない。必ず `###`（3つ）。
- **swap は作らない（2026-10-04〜）**: vault のノートは `setlocal noswapfile`。
  強制終了しても `.swp` 残骸も E325 も出ない（失うのは最大で自動保存間隔ぶん）。
  アプリとの衝突検知は `~/.vim/simple_yurii_note/locks/<sha256(abs path)16桁>.lock`
  （PID 入り）で行い、アプリは PID が生きているロックだけ有効とみなす。
  残骸ロックと旧 `.swp` は Vim 起動時の `cleanup_stale_locks()` が掃除する。
  **`-es`（バッチ）では VimEnter が発火しない**ので、掃除の検証は pty で行うこと。
- **起動時に端末応答が画面へ生エコーされる（2026-10-04 修正）**: Vim は起動直後に
  端末へ DA2 / OSC 10,11 / CPR を問い合わせる。`cleanup_stale_locks()` は VimEnter で
  必ず走り、`system('kill -0 …')` を呼ぶ一瞬だけ端末が cooked モード（echo 有効）へ
  戻るため、遅れて届いた応答（`^[[3;1R^[[>1;115;0c^[]10;rgb:…` 等）が1行目などに
  生エコーされ残る。`s:pid_alive()` は Linux では `/proc/<pid>` を見る実装にして
  `system()` を廃止した（`/proc` が無い環境のみ従来の `kill -0` へフォールバック）。
  **起動経路の外部コマンドはゼロが正**。再現は pty で応答を 3〜5ms 遅らせると出る
  （早すぎると Vim が消費し、遅すぎると raw モード中なので出ない）。
- **自動保存・バックアップ（2026-10-04、2026-10-06 拡張）**: Vim は**約1.5秒無操作**で
  vault 配下の `.md` / `.csv` を自動 `update`（`g:simple_yurii_note_autosave` / `_delay` で調整。
  同期が走るのは `.md` だけ）。**挿入・置換中でも保存する**（`silent! update` は書くだけで
  バッファを変えないので安全。ターミナルを×で閉じる＝SIGHUP は Vim 側でフックできず、
  ここを後回しにすると未保存の窓が広がるため）。**Esc（挿入モードを抜けた時）・
  バッファ/ウィンドウを離れるとき・フォーカスを失ったときは即保存**（リンク移動は
  `:buffer` 等だと `'autowriteall'` が効かない）。**保存が要る瞬間は実行の直前に書く
  （2026-10-06〜）**: `gm`（既定アプリ。`.md` はブラウザ、`.csv` は LibreOffice 等が
  disk を読む）・`\A`（アプリ起動）・`\tD`（rename 前に書き、最新の編集をゴミ箱へ）・
  `:UpdateAll`（同期は disk を正とする）は `simple_yurii_note#save_current_note()` を
  先に呼ぶ。自動保存の対象判定は `simple_yurii_note#is_autosave_target()`（vault 配下の
  .md/.csv）。**`:q!` / `:bd!` の破棄は破棄のまま**（失うのは最後の区切り以降＋
  クラッシュ/電源断のみ。swap を作らないため SIGTERM/SIGHUP は Vim 側でフックできない）。
  **ソフト削除直前の保存（2026-10-06〜）**: アプリは削除前に保留編集をフラッシュする。
  **vault は git 管理**に
  なり、`yurii-note-backup.timer`（2分）が変更を commit して
  `~/files/yurii-note/.git` と `~/.vim-simple-yurii-note/yurii-note-backup.git`（bare ミラーへ
  `backup` remote push）の2か所へ保存する。アプリの削除は `.trash/` へのソフト削除。
  復元は `yurii-note-restore`（fzf）または `git restore`。`.pkm_*.json` / `.undo/` / `_tmp/` /
  `.trash/` / `*.swp` は `.gitignore`。**vault で `git status` を走らせるとノート差分が出る
  のは正常**（プラグイン用リポジトリではない）。
- **ゴミ箱（`\tr` / `\tD`、2026-10-04）**: Vim 側の削除は `<root>/.trash/` への**ソフト削除**
  （`simple_yurii_note#trash_current()`。ファイル名はアプリと同じ `<日時>_<名前>`）。
  `\tD` は今のノートをゴミ箱へ移して全体を同期（消えたノートへのリンク行は掃除される）。
  `\tr` はゴミ箱を fzf で覗き（プレビュー付き）、`⏎` で vault 直下へ復元して開く
  （接頭辞 `<日時>_` / `<日時>_<n>_` を外して戻す）。`.trash/` はドット始まりなので
  **検索（`note_search.py`）・同期・一覧・グラフに出ない**。`\tD` は `\tdr`/`\tdc`
  （表の行・列削除）と 1 文字目が被るので `\tD`（大文字）にしている。
  **注意**: シェルから直接 `rm` した場合はゴミ箱を通らない。Vim の `:!rm %` は
  下記ガードでゴミ箱へ回る。
  **`\e`（`expand_v2.py`）と `\se` / `:ExpandLinks`（`expand_s.py`）の展開出力は
  `.trash/T_*.md`（`\e` は 2026-10-06〜、`\se` は 2026-10-04〜）**。
  使い捨ての展開ファイルが vault 直下や `_tmp/` に溜まらず、sync・検索・一覧に出ない。
  **罠（2026-10-05 修正）**: `\tr` の fzf `options` は**文字列**で渡るため、`--delimiter=\t` と
  書くと shell がバックスラッシュを食って区切りが正規表現 `t` になり、パスが最初の `t`
  （`yurii-note` の t）で切れて `sed: /home/yurii/files/yurii-no を読み込めません` になる
  （`--accept-nth=1` の復元パスも同じ理由で壊れる）。文字列なら `--delimiter="\t"` と
  ダブルクォートで包むか、options を**リスト**にして fzf.vim に shellescape させる
  （前者の例: `simple_yurii_search.vim` の `s:fzf_options`、後者: `s:note_search_run`）。
- **`:!rm` もゴミ箱へ（rm ガード、2026-10-04）**: 非対話 bash が `$BASH_ENV` を読む性質を使い、
  プラグインが `$BASH_ENV` を `plugin/simple_yurii_note/shell/yurii-note-rm-guard.sh` に設定する。
  Vim の `:!rm %` / `:silent !rm %` で **vault 配下の `.md` だけ** `<root>/.trash/` へ退避し、
  それ以外（フラグ・ディレクトリ・他ファイル）は本物の `rm` に渡す。vault は `$YURII_NOTE_VAULT`
  （`s:get_pkm_root()` が設定）で判定。`ShellCmdPost` でファイルが消えていたらバッファを閉じて同期する
  （`simple_yurii_note#after_shell_rm()`）。無効化は `g:simple_yurii_note_rm_guard = 0`
  または `YURII_NOTE_RM_NO_GUARD=1`。
- **`za` / `zA` / `zp` はクリップボード／ヤンク優先（2026-10-04）**: `s:pick_one_link()` は
  まず `s:clipboard_text()`（wl-paste → `+`/`*` → `"`）から `.md` リンクを探し、無ければ
  カーソル下のリンクを使う。**リンク上にカーソルがあってもコピー／ヤンクしたリンクを貼る**。
- **未使用 yomi の掃除（2026-10-04 修正）**: `_used_display_names(notes, incoming)` は
  各ノートの `title` を **incoming（本文からの被リンク）があるときだけ**使用中とみなす。
  リンクの無いノートの title の yomi も同期で消える（従来は全 title を無条件で残していた）。
- **`<Space>` 検索はリンク先の本文も対象（2026-10-04）**: 今のノートのリンク先を
  `note_search.py --only <paths>` で絞り、**タイトル優先（タイトル一致語数順）で
  本文も検索**する。リンク先が 0 件ならメッセージ。`--only` に列挙した絶対パス以外は対象外。


- **Parent に勝手に足されると思っている**: Parent は手書き。自動では増えない。
- **BackLink に Parent の相手が出ると思っている**: 出ない（除外される）。
- **`### Related` は `Parent` と `BackLink` の間に parse する（2026-10-04）**: `zr`
  （`za` / `zA` / `zp` の位置キー `r`）で両ノートに相互追加するセクション。
  **対称管理**: 片側にしか無いリンクは sync が外す（`_prune_one_sided_related()`。
  2026-10-04 ユーザー報告「片方から消しても残る」の修正）。片側だけ手で足しても
  次回同期で消えるので、追加は必ず `r`（両側に書く）で行う。
  `simple_sync` / `web/src/sync.js` / アプリ `app.js` の保存組み立ての**3か所すべて**が
  Related を知らないと、Parent に飲まれて保存時に消える。見出しは**中身があるときだけ**
  描画（空になったら sync が外す）。リンクは incoming に数えない（BackLink に出さない）が、
  outgoing には数える（相互ペアを BackLink に重複させない）。
- **`input()` の第3引数は補完であって cancelreturn ではない（2026-10-04）**: `zy`/`zY` が
  `input(prompt, default, "\x01")` で `E180: 無効な補完指定です: ^A` になっていた。
  Esc のキャンセル値を返したいときは `inputdialog(prompt, default, cancelreturn)` を使う
  （端末でも Esc → cancelreturn が返る。空 Enter と区別できる）。
- **`gm` はカーソル下を見ない（2026-10-04 仕様変更）**: 昔はカーソル行の URL/Markdown
  リンクを既定アプリで開いていたが、行内リンクの上にいるだけで別ノートが開く事故が
  あったため、**常に今のノートだけ**を既定アプリで開く（`plugin/other.vim`）。
- **zT の反映**: タイトル変更は simple_sync 経由で本文・Parent・BackLink に追従する。
  旧エンジン（`sync_vault`）を走らせると壊れるので注意（`retitle_links`/`new` は simple_sync に切替済み）。
  追従判定は `.pkm_title_state_v2.json`（前回 sync 時のタイトル）に依存する。この記録が
  古い/無いと、旧タイトル表示の本文リンクを「手書き名」と誤判定して更新しない。
  **simple_sync も毎回この状態を更新・保存する（2026-09-28 修正）**。
- **`\e`（expand_v2.py）も現行形式のパーサを使う（2026-10-06 修正）**: 以前は旧 v2 の
  `parse_note`（こっちにとって/そっちにとって の `up`/`down`）で読んでいたため、現行
  ノートでは「子」が `### BackLink`（自分を mention した側）を掘り、`### Related` が
  親に混ざるなど**方向が逆**だった（詳細モードが特に壊れる。シンプルは和集合なので
  実害が出にくい）。現行エンジンと同じ `_simple_parse` に切り替え、親=`### Parent` /
  子=本文リンク / 文中=`### BackLink` / 関連=`### Related` の**4方向独立**とした
  （詳細モードは深さ4つ。`related` が無い旧 `.pkm_expand_prefs.json` は 0 として読む）。
  関係リンク欄も親/関連/子（本文）/バックリンク の 4 区分で出す。回帰は `test_expand_v2.py`
  （旧テストは `sync_vault` 前提だったので `simple_sync`＋現行形式に書き換えた）。
  **旧 `parse_note` は `sync_vault` 系だけのもの**。展開に限らず「ノートを読む」
  新機能は `_simple_parse` を使うこと。
- **Yurii_PKM と simple を混同**: コマンド名（`:Yurii*` vs `:Simple*`）、関数（`yurii_pkm#` vs `simple_yurii_note#`）、
  状態ディレクトリ（`~/.vim/yurii_pkm` vs `~/.vim/simple_yurii_note`）は**別**。
- **index は同期が書き換えない**: 本文はそのまま。子の追加はコマンド（`zn`/`zp`）が行う。
- **ハブ（`\H` / `\1`〜`\9` / `\0`）は Index ごと（2026-09-27）**: 以前は
  `hubs.json` が全 Index 共通だった。`{ <root>: { "1": path } }` の入れ子にし、

- **状態ディレクトリは `~/.vim/simple_yurii_note`（2026-09-27 訂正）**: この Vim は
  `exists('*stdpath')` が 0 のため、`s:state_dir()` はフォールバックの

### 2026-10-03 追記セッションの結果（完了）

### タイトル変更の反映（2026-09-28 修正）

- 症状: `zt`/`zT` でノートのタイトルを変えても、そのノートを指す**本文リンク**の
  表示名が旧タイトルのまま残る（`### Parent` は `_preserve_parent` が常に追従していた）。
- 原因: 現役 `simple_sync` の `_update_body_link_names()` の追従条件が
  `disp == Path(base).stem` の 1 つだけだった。プラグインが作るリンクは
  `[タイトル](file.md)` なので最初から `disp != stem`。つまり**一度も追従しない**。
- 旧エンジン `sync_vault` は `_tracked_disp()` ＋ `.pkm_title_state_v2.json`（前回 sync 時の
  タイトル）で「追従してきた表示名」と「手書き名」を区別していた。この仕組みを
  `simple_sync` に移植した。追従条件は
  「`disp == 現在タイトル` or `disp == 前回タイトル` or `disp == stem`」。
- `simple_sync` は毎回 `.pkm_title_state_v2.json` を読み、変化があれば保存する。
  **注意**: この記録が無い/古い vault では初回のタイトル変更が追従しないことがある。
  一度 sync を走らせれば記録が現タイトルで更新され、以降は追従する。
- 回帰テストを `test_note_format_v2.py` に追加（`test_simple_sync_retitle_*`）。

## よみ順ソート（Index / 2026-10-03）

Index（`index.md`）のリンクを**表示名のよみ順**に並べる機能。`\S`（ノーマル=バッファ、

## 1万行 Index の軽量化（2026-10-06）

計測用の合成 vault（`~/Desktop/pkm-scale/`、1 万ノート・Index が 1 万リンク）で
顕在化した重さを直した。計測は `vim -es` 内の `reltime()`（関数）と pty 上の
Vim（描画）で行った。

- **conceal（表示名だけ表示）**: `g:simple_yurii_note_markdown_conceal_max_lines` の
  既定を 2000 → **20000**（`0` で無制限）。旧既定では 1 万行の `index.md` で conceal が
  切られ、ノーマルモードでも `[表示名](id.md)` の `()` が見えていた。conceal の描画は
  1 万行でも j / G / C-f / C-l で遅くならない（可視行しか処理しない）ことを実測で確認。
- **`_` 入りの日本語表示名が conceal を殺す罠（2026-10-06）**: Vim の markdown 斜体
  （`markdownItalic`）の開始条件は `\w\@<!_\S\@=` で、`\w` が ASCII 基準のため
  日本語の直後の `_`（例 `ミカンの考察_01811`）で斜体が始まってしまう。閉じ `_` が無いと
  空行まで行をまたいで斜体領域になり、**その中ではトップレベルの構文が効かない**ため、
  後続のリンクが `[表示名](file.md)` のまま表示された（Index は front matter に `_` が
  無いので気づきにくく、ノートだけ壊れて見えた）。`yuriiLinkRegion` に
  `containedin=markdownItalic,markdownBold,markdownBoldItalic` を付けて、斜体/太字の
  中でもリンクとして表示するようにした（コードブロックには入らない）。最小再現は
  「`_` がリンクより前の本文にあるノート」。
- **リンク移動（数字ジャンプ・ヒント）**: `s:v2_boundaries()` が全行を Vimscript ループで
  trim 比較していて、1 万行で **245ms/回**かかっていた（ヒント更新・数字キーのたびに
  走る）。後方 `search()`（C 実装）で up/down の最終マーク行を引く方式に変えて **24ms**。
  行配列に対する `s:v2_boundaries_in_lines()`（旧来の実装）は walk 用に残す。
- **リンクを開くたびの `s:find_section_line()`**: 全行を Vimscript ループで trim 比較して
  おり **0.31s/回**。`open_link_under_cursor` は `s:in_up_section` / `s:in_back_section` 経由で
  これを 2 回呼ぶため、Index からのリンク移動は 1 回 **0.6s 超**かかっていた
  （「まともに使えない」の主因）。後方 `search()` で「最後の一致行」を探し、
  フェンス内なら手前を再探索（`s:line_in_fence()` も `search()` で数えるだけ）に置換
  → **8ms**。旧実装との結果一致は 15 レイアウト × 8 セクション名で確認済み。
  `s:section_search_pat()` が `bare_section_name` と同じ字面（`#` の有無・`:`
  の有無・大文字小文字）を再現する。
- **`\S`（よみソート）**: `japanese_yomi.py` にプロセス内メモ `_note_entry()` を追加し、
  `get_yomi` / `set_yomi` / `list_yomi_names` が同じノートの front matter を 1 回しか
  読まないようにした（`set_yomi` は書き込み後もメモを更新）。`reading_for()` は
  かな・英数のみの文字列を pykakasi に通さない（登録済み `yomi:` の再変換を回避）。
  1 万リンクで初回 8.1s → **3.7s**、2 回目 4.8s → **2.0s**。Vim 側は実行前に
  「並べ替え中…」を `redraw` 表示し、無反応に見えないようにした。テスト用に
  `japanese_yomi.clear_memos()` がある。
- **同期のパースキャッシュ**（`.pkm_parse_cache_v2.json`）: 鮮度判定を mtime+size から
  **内容ハッシュ（blake2b 8byte）** に変更。mtime は FS の時刻刻みが粗いと同サイズの
  編集（OldTitle→NewTitle）を取りこぼし、テストが落ちた（`/tmp` は coarse）。
  読み込みは全ファイル分行うが、内容が同じならパースを省く。全件キャッシュヒットかつ
  書き換えゼロなら数 MB の JSON を書き直さない。1 万台で warm 3.4s → 2.1s。
  `_nid()` は `pathlib.relative_to`（1 万回で秒級）を避けて `os.path.relpath` を優先。
- このとき前セッションの未コミット変更が壊れた状態で残っていた（`autoload` の
  `open_web` 重複で E126、`note_format_v2.py` の `for` 直後の構文エラー）。修復してから
  作業した。**未コミットのままセッションを終えない**（変更したら push まで）。

## 見出しアンカーリンク（`#スラッグ` / `zo`、2026-10-07）

`[表示名](note.md#スラッグ)` でノート内の見出しへ飛べるようにした（`zo` で選択）。
普通の Markdown ビューア（GitHub / VS Code）でも動くよう、fragment は GitHub 互換
スラッグ（`github-slugger` の近似）。

- **同期は無変更**: Python / JS の sync は元から `tg.split("#", 1)[0]` で解決し、
  表示名書き換え時は `tg` を丸ごと使う（`#` 保持）。子・incoming・Parent・Related・
  掃除・タイトル追従はそのまま。回帰テストを `test_note_format_v2.py`
  （`test_simple_sync_anchor_*`）に追加して固定した。
- **BackLink だけは `#` が消える**: `_simple_render` が BackLink 行を作り直すため。
  `zo` は BackLink 内で警告して何もしない（本文 / Parent / Related は保持）。
- **Vim 側の要点**:
  - `s:gh_slug()` … GitHub 互換の近似（小文字化 → ASCII 句読点
    `[!-,.\/:-@\[-\^`{-~]` と日本語の約物を除去 → 空白を `-`。`-` `_` は残す）。
    重複は `s:slugger_unique()` が github-slugger と同じ `-1` `-2` を付ける
    （ファイル順。フェンス内・一覧に出さない見出しも番号に数える）。
  - `s:jump_to_fragment()` … スラッグ一致（`s:line_in_fence()` でフェンス除外）
    → 生見出し一致（`\V`）→ `<a id="...">` の順。最後ので `\e` の `#note-N` も開ける。
  - `s:resolve_existing_link_target` / `s:resolve_link_for_navigation` /
    `resolve_link` は `#` を落としてから解決する（既存の `\.md\(#.*\)\?$` 判定も活きる）。
  - `zo`（`link_to_outline`）は fzf の右ペインで `tail -n +{4} {3} | head -40` を
    preview 表示（source は `表示 \t スラッグ \t パス \t 行番号`、`--with-nth=1`）。
    fzf 無しは `inputlist`。非対話版は `link_to_outline(スラッグ)`（テスト用）。
  - 見出しの列挙は「タイトルと同じ H1」「`s:is_known_section_header_text()`
    （Parent/Related/BackLink 等）」「コードフェンス内」を除外。
- **検証**: `vim -i NONE -es -S` のヘッドレス（script-local は `<SNR>` で呼ぶ）。
  `winrestview()` は `-es` では期待どおり動かないことがある（対話 Vim では正常）。

## 紙のPKM（フォルゲゼッテル）連携（2026-10-07）

紙のフォルゲゼッテル（スキャン画像）を SYN に取り込む。元は別リポジトリ
`Yurii7812/folgezettel-image-renamer`（Windows/Tk、`ZK_<id>.md` を作る）。SYN 版は
「各スキャンは**タイムスタンプ名ノート**（title=ID）」に変更し、vault 直下（フラット）で完結する。

### ファイルとコマンド

- `plugin/simple_yurii_note/python/paper_pkm.py` … コア。`create` / `regen` / `ids`。
- `plugin/simple_yurii_note/python/folgezettel_scan.py` … 番号付け Tk GUI（`\f`）。
- Vim: `\F`=`:SimplePaperIndex`、`\f`=`:SimpleScan`。`Index_write.md` の保存時は
  autosync が `paper_pkm.py regen ROOT` を起動する（`update_one` の代わり。regen が
  同期込み）。
- `\S` は `Index_write.md` のときだけ `--keyword-lines` を渡す（`japanese_yomi.sort_lines`
  の `extra_key_fn`）。`\S` は `Folgezettel-Index.md` では警告して何もしない（生成物）。

### データ設計

- スキャンノート: タイムスタンプ名（`%y%m%d%H%M%S`）、front matter `title: <ID>`・
  `folgezettel: <ID>`、本文 `# <ID>` ＋ `![](<ID>.jpg)` ＋
  `<!-- PAPER:START -->…<!-- PAPER:END -->`（親子リンク）。
- 紙PKM Index: タイムスタンプ名、`paper_index: true`。`Index_write` と
  `Folgezettel-Index` へのリンク＋キーワードリンク（管理ブロック内）。
- キーワードグループ: `attribute: group`・`paper_keyword: <表示名>`。複数IDのときだけ作る。
- `Index_write.md` は手書き（プログラムは作成時のみ触る）。行は
  `キーワード(よみ): 1,1a10b,3`。`(…)` が本体のよみ（pykakasi）と一致すればよみ、
  しなければ修飾語として**本体のよみ**で並べる（オザーク(ドラマ) → おざーく）。
- 生成物は管理ブロック（`<!-- PAPER:START/END -->`）の中だけ書き換え、外の手書きは残す。

### 罠（重要）

- **sync はグループ（`attribute: group`）からのリンクを相手の `### Parent` に自動追加し、
  リンクが消えても行を消さない**。キーワードから外した ID に古い Parent 行が残るため、
  regen が `_prune_stale_group_parents()` で「今のグループに無い ID のグループ Parent 行」
  だけ掃除する（sync 側は触らない）。紙PKM Index 自体は group にしていない
  （group にすると単一IDリンクの相手にも Index が Parent として自動追加され、
  手動管理の親子と混ざるため）。
- **`reading_for()` はカタカナのみの文字列を pykakasi に通さない**（`_NO_CONVERT_RE`
  の近道）。よみを fm に書くときは `kata2hira()` を通してひらがなに統一する
  （オザーク → おざーく）。
- **`\f` は `\fs`（全文検索）と前置きが被り、最大 `timeoutlen`（既定500ms）待つ**。
  `\F` は即時。`\fs` を消す/移すなら `\f` の待ちは消える（今は許容）。
- キーワード行と普通の文の区別は「ID 部分が `\d+(?:[a-z]+\d+)*[a-z]*` のカンマ/空白区切り」
  で行う。`キーワード: フォルゲゼッテル` のような説明行は対象外（そのまま残る）。
- **キーワード行の誤マッチ（2026-10-07 修正）**: 当初 `.+?` の後退で front matter の
  `time: 2026-01-01 00:00:00` がキーワード行（key=`time: 2026-01-01 00`、ids=`00`）と
  誤認され、`\S` で front matter が混ざった。キーと ID 部に `:` を許さない正規表現
  （`[^:]+?` / `[^:]+`）にして修正。テスト（test_sort_yomi / test_paper_pkm）で固定。
- 画像は EXIF 日時を front matter `time:` に使い、**ファイル名は今の時刻**（タイムスタンプ名）。
- GUI は起動時に必ずフォルダ選択を出す（キャンセル時は前回フォルダ）。
