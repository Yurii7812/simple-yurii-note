# 06 引き継ぎ（新しいAI向け）

## 最初にやること

1. このフォルダの `README.md` → `01`〜`05` を読む。
2. プラグイン実体 `~/.vim-simple-yurii-note/simple-yurii-note` を把握。
3. ノート実体 `~/files/yurii-note` を見る（`index.md` が入口）。
4. `~/.config/opencode/AGENTS.md` と skills（特に `pkm-system`）を読む。
5. 変更したら **push まで**（日本語コミット）。

## 重要な不変条件

- ノートのセクションは `### Parent` / `### BackLink`（`#` 3つ）。**`### Child` は使わない**。
- 子は**本文リンク**。本文に書けば子になる。
- `### Parent` は**手書き管理**。同期は追加・削除しない（表示名だけ追従）。
- `### BackLink = incoming − Parent`。Parent にあるものは BackLink に出さない。
- `index.md` は**セクションを持たない**（本文の裸リンクが子）。
- `zn`/`zk` の `Enter` は「本文があれば本文の下に空行1つ＋リンク / 無ければ余白を保って Parent 直上にリンク」。

## よくある落とし穴

- **`##`（2つ）で書く**: 同期が反応しない。必ず `###`（3つ）。
- **Parent に勝手に足されると思っている**: Parent は手書き。自動では増えない。
- **BackLink に Parent の相手が出ると思っている**: 出ない（除外される）。
- **zT の反映**: タイトル変更は simple_sync 経由で本文・Parent・BackLink に追従する。
  旧エンジン（`sync_vault`）を走らせると壊れるので注意（`retitle_links`/`new` は simple_sync に切替済み）。
- **Yurii_PKM と simple を混同**: コマンド名（`:Yurii*` vs `:Simple*`）、関数（`yurii_pkm#` vs `simple_yurii_note#`）、
  状態ディレクトリ（`~/.vim/yurii_pkm` vs `~/.local/share/vim/simple_yurii_note`）は**別**。
- **index は同期が書き換えない**: 本文はそのまま。子の追加はコマンド（`zn`/`zp`）が行う。

## このセッション（2026-09-26/27）で実際に踏んだこと

- **`sync_vault` を直しても反映されない（2026-09-27）**: `update ROOT` / `update_one` は
  `note_format_v2.py` の **`simple_sync()`** を呼ぶ。`sync_vault()` は旧 v2 エンジンで、
  `migrate` だけが呼ぶ。Index → Parent の修正もここに入れた（`simple_sync()` 内）。
- **テストが 1 つ前から失敗している（2026-09-27）**: `test_note_format_v2.py` の
  `test_down_side_order_is_sticky` が `dn.index("20250199.md")` で ValueError。
  変更前から同じ。落ちているのはこの 1 つだけなので、最初の 1 つがこれなら
  「自分の変更のせい」と決めつけない。
- **`~/files/yurii-note` に UTF-8 でない `.md` が混じっている**: 全文を `read_text(encoding="utf-8")`
  で回すスクリプトは `UnicodeDecodeError` で落ちる。`except UnicodeDecodeError: continue` を入れる。
- **ノートは Git 管理外**（`~/files/yurii-note` は Git repo ではない）。整形を戻すときは
  変更したファイルを 기억しておくか、先にコピーへ試す。
- **`za` と `zp` は対になる操作（2026-09-27）**:
  - `za` = 今のノートに（クリップボードの）リンクを足す ＝ **今のノートの子**
    （置き場所は `### Parent` の直前）
  - `zp` = **今のノートを相手の `### Parent` に足す**（相手はカーソル下のリンク、無ければ
    クリップボード）＝ 今のノートが相手から見て子
  - `zp` の実体は `simple_yurii_note#add_to_parent()`。以前は `add_clipboard()`
    （今のノートに相手のリンクを足す＝`za` と同じ向き）が割り当てられていた。
- **`za` の置き場所は `### Parent` の直前（2026-09-27）**: 現ノートの `### BackLink` には
  入れない。`s:insert_link_before_up_note()` が `### Parent` の 1 行上に挿入する。
  本文末尾が散文のときだけ空行を 1 つ開けてから置く（リンクで終わるときは空行を挟まない）。
  重複は `s:buffer_has_link()` で弾く（バッファ全体・解決先一致で見る）。
  相手ノートにも何も書かない（相手側の BackLink は sync が入れる）。
- **`g:simple_yurii_note_format` の既定は 'v2'（2026-09-27）**: `s:pkm_format()` は
  'v2' か 'v1' しか返さない。現在のノート実体は `### Parent` / `### BackLink` のみで
  動かしているのに、プラグイン内部は v2 とみなしている。キーの実装を触るときは
  「どちらの分岐に落ちるか」を必ず確認する（テストは `let g:simple_yurii_note_format`
  を明示した一時 vault を作って headless で回すと安全）。
- **Index が Parent に入らない／BackLink に入ってしまう時（2026-09-27）**: `index.md` の
  本文リンクは、子側の `### Parent` 先頭へ `[Index](index.md)` として入る（BackLink には出ない）。
  `simple_sync()` の `index_of` で組み立てている。`index_of` を作らないと Index は
  incoming（＝BackLink）として扱われる。

## 検証（整形を確かめる）

```bash
# 本文末尾が散文なのに ### Parent が直にくっついているノートを列挙する
cd ~/files/yurii-note && python3 - <<'EOF'
import pathlib, re
L = re.compile(r"^\s*(\[[^\]]*\]\([^)]+\))\s*(?:—\s*\S+)?\s*$")
bad = []
for p in sorted(pathlib.Path('.').rglob('*.md')):
    try:
        ls = p.read_text(encoding='utf-8').split('\n')
    except UnicodeDecodeError:
        continue
    for i, l in enumerate(ls):
        if l.strip() == '### Parent' and i > 0 and ls[i-1].strip() != '' and not L.match(ls[i-1]):
            bad.append((p.name, i + 1))
print(bad)
EOF
```

出力が `[]` なら整形は保たれている。sync は 2 回走らせて **2 回目が 0 changes** であることを
確認する（冪等性のチェック）。

3. 専用 Vim を再起動して確認。
