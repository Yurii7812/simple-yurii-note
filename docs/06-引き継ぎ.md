# 06 引き継ぎ（新しいAI向け）

## 最初にやること

1. このフォルダの `README.md` → `01`〜`05` を読む。
2. プラグイン実体 `~/.vim-simple-yurii-note/simple-yurii-note` を把握。
3. ノート実体 `~/files/yurii-note` を見る（`index.md` が入口）。
4. `~/.config/opencode/AGENTS.md` と skills（特に `pkm-system`）を読む。
5. 変更したら **push まで**（日本語コミット）。

## 重要な不変条件

- ノートのセクションは `### Parent` / `### BackLink`（`#` 3つ）。**`### Child` は使わない**。
- 子は**本文リンク**。本文に書けば子になる。
- `### Parent` は**手書き管理**。同期は追加・削除しない（表示名だけ追従）。
  ただし**消えたファイル（存在しない `.md`）へのリンク行は掃除する**（`_prune_dangling()`）。
- `### BackLink = incoming − Parent`。Parent にあるものは BackLink に出さない。
- `index.md` は**セクションを持たない**（本文の裸リンクが子）。
- `zn`/`zk` の `Enter` は「本文があれば本文の下に空行1つ＋リンク / 無ければ余白を保って Parent 直上にリンク」。

## よくある落とし穴

- **`##`（2つ）で書く**: 同期が反応しない。必ず `###`（3つ）。
- **Parent に勝手に足されると思っている**: Parent は手書き。自動では増えない。
- **BackLink に Parent の相手が出ると思っている**: 出ない（除外される）。
- **zT の反映**: タイトル変更は simple_sync 経由で本文・Parent・BackLink に追従する。
  旧エンジン（`sync_vault`）を走らせると壊れるので注意（`retitle_links`/`new` は simple_sync に切替済み）。
- **Yurii_PKM と simple を混同**: コマンド名（`:Yurii*` vs `:Simple*`）、関数（`yurii_pkm#` vs `simple_yurii_note#`）、
  状態ディレクトリ（`~/.vim/yurii_pkm` vs `~/.vim/simple_yurii_note`）は**別**。
- **index は同期が書き換えない**: 本文はそのまま。子の追加はコマンド（`zn`/`zp`）が行う。
- **ハブ（`\H` / `\1`〜`\9` / `\0`）は Index ごと（2026-09-27）**: 以前は
  `hubs.json` が全 Index 共通だった。`{ <root>: { "1": path } }` の入れ子にし、
  `s:hub_root_key()`（現在の PKM ルート）単位に分けた。`\H` は今のルートの表へ登録し、
  別の Index を開けばその Index 専用のハブになる。旧フラット形式は初回に現在の
  ルート配下へ自動移行する。
- **状態ディレクトリは `~/.vim/simple_yurii_note`（2026-09-27 訂正）**: この Vim は
  `exists('*stdpath')` が 0 のため、`s:state_dir()` はフォールバックの
  `~/.vim/simple_yurii_note` を使う。`XDG_DATA_HOME` を変えても効かない。
  headless テストは `hubs.json` / `recent.json` / `root.txt` を汚すので、
  実行前に退避し後に復元する（`hubs.json` はハブ登録が実データなので特に注意）。

### キー設計の要点

- `za` = 今のノートにリンク 1 本を足す。`zp` = それに追加して
  **今のノートを相手の `### Parent` に書く**。違いはこの 1 点だけ。
- リンクの候補は「**カーソル下のリンク → クリップボード**」。クリップボードを
  全部ループで回すのは「変」なので、`s:pick_one_link()` で 1 本だけにした。
- 位置キーは `h`（カーソル直下）/ `Enter`（本文の最後）。`p`（`### Parent` 末尾）と
  `o`（置かない）は `zn` / `zk` のみ。`za` / `zp` / `\p` は `h` / `Enter` だけ。
- `zn` / `zk` で新ノート側に元ノートをどう書くかは位置キーで決まる。
  `h` / `Enter` は元ノートが親なので新ノートの `### Parent` に元ノートを 1 行入れる。
  `p` は元ノートが子なので新ノートの**本文リンク**に入れる（`### Parent` は空）。
  `o` はリンク無し（孤立）。
  「今のノートで Parent に置いたから新ノートは Parent」のような分け方はしない。

### 整形（見た目）

- 本文的末尾にリンクを置いたら、`### Parent` の直前に**空行 1 行**。
  既存の空行があれば足さない（`s:ensure_blank_before_up()`）。
- `p` の新規ノートは、テンプレートの余白を `s:simple_body_append_to_file()` が
  次の並びに置き換える（潰さない、空行は累積しない）。
  グループ（`zk`）は `H1` / 空行 / リンク / `### Parent`（リンクと Parent が隣り合う）。
  普通のノート（`zn`）は `H1` / 空行 / リンク / 空行 / `### Parent`。
- `h` / `Enter` の新規ノートは本文にリンクを置かない（余白はテンプレートのまま）。

### 失敗したこと（症状 → 原因）

| 症状 | 原因 |
| --- | --- |
| 新ノートが自己リンク `[A](B.md)`（B が新ノート自身）になった | `s:make_link_from_dir()` の第 1 引数は「リンクの行き先」。新ノート自身の `l:file` を渡していた。`l:cur` に直した |
| `p` の新ノートがリンク無しの空本文になった（2026-09-27） | `s:simple_body_append_to_file()` の `while` を `endfor` で閉じていた（E732）。呼ぶと例外で中断。`endwhile` に修正 |
| `\p` / `za` が「クリップボードが空」／古い内容になる | Wayland なのに Vim の `@+`（XWayland）を先に読んでいた。`wl-paste` 等を**先に**読むよう変更 |
| `za` / `zp` が何も起きない（テスト時） | `feedkeys(..., 'x')` は `getchar()` に届く前に消費される。`feedkeys('p')`（'x' なし）で queue すれば読める |
| テスト中に `E353: レジスタ " には何もありません` | `@"` を直接読むと空で例外。`getreg('"')` を使う |
| `sync` でなおしてもノートが変わらない | `update` は `sync_vault()` ではなく **`simple_sync()`** を呼ぶ（`migrate` だけが `sync_vault`） |

### 検証のしかた

- データ変更は**必ず `/tmp` にコピーしてから**試す（`~/files/yurii-note` は Git 管理外）。
- sync は**2 回走らせて 2 回目が 0 changes** であることを確認する（冪等）。
- `zn` などの位置キーは headless でも `feedkeys('p')`（'x' なし）→ 関数呼び出しで
  検証できる。うまく取れないときはロジックを Python で書き直して確認してもよい。

## 検証（整形を確かめる）

```bash
# 本文末尾が散文なのに ### Parent が直にくっついているノートを列挙する
cd ~/files/yurii-note && python3 - <<'EOF'
import pathlib, re
L = re.compile(r"^\s*(\[[^\]]*\]\([^)]+\))\s*(?:—\s*\S+)?\s*$")
bad = []
for p in sorted(pathlib.Path('.').rglob('*.md')):
    try:
        ls = p.read_text(encoding='utf-8').split('\n')
    except UnicodeDecodeError:
        continue
    for i, l in enumerate(ls):
        if l.strip() == '### Parent' and i > 0 and ls[i-1].strip() != '' and not L.match(ls[i-1]):
            bad.append((p.name, i + 1))
print(bad)
EOF
```

出力が `[]` なら整形は保たれている。sync は 2 回走らせて **2 回目が 0 changes** であることを
確認する（冪等性のチェック）。
